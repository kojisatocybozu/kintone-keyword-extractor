# kintone Keyword Extractor

kintone の添付ファイルからテキストを抽出し、Amazon Bedrock
を利用して検索用キーワードを生成し、kintone レコードへ保存する AWS
Lambda 関数です。

## 1. システム概要

-   **Lambda 関数名:** `ks-kintone-keyword-extractor`
-   **AWS リージョン:** `ap-northeast-1`（東京）
-   **kintone アプリ ID:** `936`
-   **主な役割:**
    指定されたレコードの添付ファイルを取得し、キーワードを抽出してレコードを更新する
-   **AI モデル:** `amazon.nova-lite-v1:0`（`BEDROCK_MODEL_ID`
    で変更可能）

### 処理フロー

1.  呼び出し元から kintone のレコード番号 (`recordId`) を受け取る。
2.  kintone アプリ `936` から対象レコードを取得する。
3.  添付ファイルフィールド `File` のファイルをダウンロードする。
4.  対応形式のファイルからテキストを抽出する。
5.  Amazon Bedrock にプロンプトと本文を渡し、検索キーワードを生成する。
6.  `SearchKeyword` などのフィールドを更新し、処理結果を記録する。

## 2. kintone のフィールド

  --------------------------------------------------------------------------------------
  フィールドコード                    用途
  ----------------------------------- --------------------------------------------------
  `File`                              入力となる添付ファイル

  `SearchKeyword`                     抽出した検索キーワードの保存先

  `KeywordExtractionPrompt`           レコードごとに指定するキーワード抽出プロンプト

  `KeywordExtractionStatus`           処理状態（`未依頼`、`依頼中`、`完了`、`エラー`）

  `KeywordExtractionDate`             抽出処理日時

  `KeywordExtractionError`            エラー内容
  --------------------------------------------------------------------------------------

アプリのフィールドコードおよび選択肢は、実際の kintone
アプリ設定と一致させてください。

## 3. 対応ファイル形式

現時点の実装で対応する形式：

-   PDF
-   Microsoft Word (`.docx`)
-   Microsoft Excel (`.xlsx`, `.xls`)
-   テキスト (`.txt`)
-   CSV (`.csv`)

PDF
の種類やファイル内容によっては、テキストを十分に抽出できない場合があります。スキャン画像のみの
PDF など、文字情報を含まないファイルは別途 OCR
が必要になることがあります。

## 4. 主な依存ライブラリ

実装で使用する主なライブラリ：

-   `axios` --- kintone REST API との通信
-   `pdf-parse` --- PDF テキスト抽出
-   `mammoth` --- DOCX テキスト抽出
-   `xlsx` --- Excel / CSV 等の読み取り
-   `@aws-sdk/client-bedrock-runtime` --- Amazon Bedrock 呼び出し

依存関係の実際のバージョンは `package.json` と lockfile
を正としてください。

## 5. 環境変数

  -------------------------------------------------------------------------------------------------------------------
  変数                                          必須 説明
  --------------------- ---------------------------- ----------------------------------------------------------------
  `KINTONE_BASE_URL`                            はい kintone のベース URL。例：`https://si-team-dev.cybozu.com`

  `KINTONE_API_TOKEN`                           はい 対象アプリのレコード取得・更新とファイル取得に必要な権限を持つ
                                                     API トークン

  `BEDROCK_MODEL_ID`                          いいえ 利用する Bedrock モデル ID。未設定時は実装のデフォルト値を使用

  `AWS_REGION`                                いいえ AWS リージョン。通常は `ap-northeast-1`
  -------------------------------------------------------------------------------------------------------------------

**注意:** API トークンをソースコード、README、Git
リポジトリ、ログに記載しないでください。トークンは Lambda
の環境変数など、適切に管理された設定として登録してください。

## 6. ビルド・デプロイ

このプロジェクトの実際の構成に合わせて、既存のビルド／デプロイ手順を使用してください。ローカル開発では会社の方針に従い
`npm` ではなく `pnpm` を使用します。

例（プロジェクトに対応するスクリプトが定義されている場合）：

``` powershell
pnpm install
pnpm build
sam build
sam deploy
```

`package.json`、ビルド設定、SAM
テンプレートが定義するコマンドや出力先を優先してください。デプロイ前に対象
AWS アカウントとリージョンを確認してください。

## 7. 呼び出し

この Lambda は、レコード番号を `recordId`
として受け取る呼び出しを想定しています。プロセッサ Lambda
からは、概ね次の JSON ペイロードで同期呼び出しされます。

``` json
{
  "recordId": "123"
}
```

`recordId` には対象 kintone レコードのレコード番号を指定します。API
Gateway
経由で利用する場合は、実装されているイベント形式に従ってください。

## 8. IAM 権限

実行ロールには、少なくとも次の操作に必要な権限が必要です。

-   CloudWatch Logs へのログ出力
-   利用する Amazon Bedrock モデルの呼び出し（`bedrock:InvokeModel`）
-   その他、実装で使用する AWS サービスへのアクセス

必要な権限は、実際のコードと SAM
テンプレートに合わせて最小権限で設定してください。

## 9. トラブルシューティング

-   **キーワードが保存されない:** kintone の API トークン権限、アプリ
    ID、フィールドコードを確認する。
-   **Bedrock 呼び出しが失敗する:** モデル ID、リージョン、IAM
    権限、モデルの利用可能性を確認する。
-   **ファイルを読めない:**
    添付ファイルの形式、ファイル内容、ファイル取得時の権限を確認する。
-   **処理状態が `エラー` になる:** `KeywordExtractionError` と Lambda
    の CloudWatch Logs を確認する。
-   **プロンプトの出力が期待と異なる:** `KeywordExtractionPrompt`
    の内容と、抽出されたテキストを確認する。

## 10. 関連プロジェクト

`lambda-kintone-keyword-processor` は、kintone の
`KeywordExtractionStatus` が `依頼中` のレコードを検索し、この extractor
Lambda を呼び出すための管理用 Lambda です。
